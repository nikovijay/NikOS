# Planning principles

| Principle | Applies when |
| --- | --- |
| **Bets have review dates.** A bet is reviewed on its date: continue, change, stop or complete, with the reason written down. A forecast is not a deadline; say which a date is. | You're scoping a bet or it's running long. |
| **Bets are grounded in evidence.** A bet cites what we saw (user quotes, numbers, results), not what we hope. | You're writing a hypothesis or the "Why we think so" section. |
| **Shipped is not success.** Delivery comes from the story maps; the outcome comes only from key result evidence. | You're reporting on a bet. |
| **Keep the original target.** A revised target never erases the one we started with. | Someone wants to move a target. |
| **Planning never blocks on a repo.** A code repo that can't be read is unresolved, not absent; plan on without it and say so. | A linked code repo can't be read. |
| **Not every bet needs an OKR.** Maintenance and risk work can stay unaligned rather than inventing a link. | You're linking a bet to key results. |
| **Stay in the area.** Key results are written where they're owned: company and department only. Teams and groups hold bets. | You're about to add a key result to a group or team. |
